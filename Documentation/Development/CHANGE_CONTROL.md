# Change Control

## When Required

Use change control for new features, changed business rules, scope movement, schema changes, security exceptions, financial formula changes, permission changes, infrastructure decisions, and requirement removal.

## Change Record

Record:

- Identifier, title, requester, and date.
- Current requirement and requested change.
- Business reason and priority.
- Affected modules, data, API, mobile/web, localization, and reports.
- Security, tenant, financial, migration, testing, and operational impact.
- Estimate, alternatives, recommendation, decision owner, and outcome.

## Process

1. Document the request without implementation.
2. Analyze impact and conflicts.
3. Obtain Project Owner and specialist approval.
4. Update requirements/ADRs/permission or traceability records.
5. Implement in an approved prompt/change.
6. Preserve tests and acceptance evidence.

Urgency does not authorize silent scope or security changes.
